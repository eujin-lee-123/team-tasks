# User Stories — Team-Tasks

## 1. 핵심 시나리오

**페르소나:** 팀원 (실무자) · 개발자 · 자신에게 할당된 일감을 매일 처리

---

### 하루 흐름 (시간 순)

| 시각 | 행동 | 앱에서 하는 일 |
|------|------|----------------|
| 09:00 | 출근 후 오늘 할 일 파악 | "내 일감" 필터로 자신에게 할당된 일감 목록을 조회한다. 마감일·우선순위 순으로 정렬해 오늘 처리할 항목을 확인한다. |
| 09:10 | 첫 번째 일감 착수 | 최우선 일감을 열어 상태를 **할 일 → 진행 중**으로 변경한다. |
| 10:30 | 블로커 발생 | 진행 중인 일감에 메모("API 응답 스펙 확인 필요 — @팀장")를 남긴다. |
| 11:00 | 신규 일감 수신 | 팀장이 새 일감을 할당했다는 알림을 확인하고 목록에서 내용을 읽는다. 현재 작업과 우선순위를 비교해 순서를 결정한다. |
| 12:00 | 점심 전 중간 저장 | 오전에 처리한 내용을 메모에 짧게 기록하고 자리를 뜬다. (상태는 **진행 중** 유지) |
| 13:30 | 오후 작업 재개 | 목록을 다시 열어 진행 중인 일감으로 바로 이동한다. |
| 15:00 | 첫 번째 일감 완료 | 작업이 끝난 일감의 상태를 **진행 중 → 완료**로 변경한다. |
| 15:05 | 다음 일감 착수 | 오전에 수신한 신규 일감을 열어 **할 일 → 진행 중**으로 전환하고 작업을 시작한다. |
| 17:30 | 퇴근 전 마무리 | 미완료 일감에 진행 메모("내일 이어서 — 50% 완료, 잔여: 테스트")를 남기고 상태를 **진행 중**으로 둔 채 저장한다. |
| 17:40 | 하루 결산 확인 | "내 일감" 목록에서 오늘 완료한 항목과 내일 이어갈 항목을 한눈에 보고 퇴근한다. |

---

### 이 시나리오에서 사용된 기능

1. 내 일감 필터 (담당자 = 나)
2. 상태 변경 (할 일 / 진행 중 / 완료)
3. 메모 입력·조회
4. 신규 할당 알림 수신
5. 우선순위·마감일 정렬

---

## 2. 결정 사항

1. **담당자도 상태를 직접 변경할 수 있는가, 아니면 팀장만 가능한가?**
   — 09:10·15:00 시점에서 팀원이 상태를 바꾸는 행동이 전제되어 있으나, 권한 정책이 정해지지 않았다.

2. **알림은 어떤 방식으로 전달하는가? (앱 내 배지·이메일·슬랙 연동 등)**
   — 11:00 시점에서 "신규 일감 알림을 확인한다"고 했으나 전달 채널이 명시되지 않았다.

3. **메모는 팀원 본인만 볼 수 있는가, 팀장과 관찰자도 열람할 수 있는가?**
   — 10:30·17:30 시점의 메모가 내부 노트인지 공유 댓글인지에 따라 데이터 모델이 달라진다.

4. **우선순위는 팀장이 지정하는가, 팀원이 직접 조정할 수 있는가?**
   — 09:00 시점에서 우선순위 순 정렬을 활용하지만, 값을 누가 입력·수정하는지 결정되지 않았다.

5. **완료된 일감은 목록에서 즉시 숨겨지는가, 일정 기간 보관 후 아카이브되는가?**
   — 17:40 시점에서 "오늘 완료한 항목을 한눈에 본다"고 했으므로 당일은 표시해야 하지만, 그 이후 보존 정책이 정해지지 않았다.
